# Проверка обновления Windows 0.1.5 / 0.1.5-test.1

Автоматический переход обязателен. Выпуск ждёт его проверки; переустановка новым установщиком эту проверку не заменяет.

## Сейчас можно выполнить: сбор фактов

1. Распакуйте весь ZIP в отдельную папку вне установленной игры, например на Рабочем столе. Оба файла `.ps1` должны лежать рядом.
2. Найдите каталог установки через свойства ярлыка игры («Расположение файла»). Нужен корень с `Update.exe`, а не `current`. Не перемещайте установленную игру и не запускайте обновление для этого шага. Игру специально запускать не нужно.
3. Откройте обычный Windows PowerShell **без повышения прав** в папке распакованного комплекта. Выполните команду, заменив пример пути на фактический:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Collect-LegacyInventory.ps1 -InstallRoot "C:\Program Files\Star Tournament" -OutputPath "$env:USERPROFILE\Desktop\StarTournament-legacy.json"
```

`Bypass` действует только для этого процесса PowerShell. Скрипт не меняет политику системы. Если Рабочий стол перенесён в OneDrive, укажите существующий каталог для результата вручную. Существующий файл результата не перезаписывается: для повторного запуска выберите другое имя.

4. Ожидаемый результат: `Inventory written: ...`, затем `qualification remains NotRun`. Верните агенту полученный JSON. Если запуск закончился ошибкой — верните её текст; не повышайте права и не меняйте разрешения папки ради отчёта.

Скрипт читает только перечисленные служебные файлы установки, SHA256/секции PE и сведения о процессах под корнем установки. Он не запускает EXE, игру, обновлятор, установщик, не завершает процессы, не меняет установку, профили или баланс и не отправляет данные в сеть. Единственная запись — новый JSON по указанному пути. Отчёт содержит путь установки (в нём может быть имя пользователя), PID и время старта процессов; сырые командные строки, содержимое профилей и произвольные поля JSON в отчёт не попадают. Недоступные наблюдения остаются `unavailable`/неполным покрытием. Файлы и процессы наблюдаются неатомарно.

Хэши комплекта находятся в `manifest.json`. `legacy-reference.json` описывает обновлятор из ранее проверенных опубликованных пакетов; совпадение с ним само по себе не доказывает исправность перехода.

## Следующий этап: изолированный автоматический переход

**Пока не запускать:** переходный пакет и безопасный перенос управления старого обновлятора ещё не квалифицированы. После отчёта агент сопоставляет реальные файлы с опубликованными пакетами и готовит точную версию пакета, канал, команду запуска и точки сбоя. До этого обновление и установка новой версии в рамках сценария не требуются.

Для этого этапа потребуется изолированная Windows-среда с точкой восстановления: предпочтительно VM со снимком и отдельной установкой нужной старой версии. Простое копирование папки игры не доказывает эквивалентность установки, прав, путей и профиля. Нужны отдельно 0.1.5 production и 0.1.5-test.1 test; неизвестная версия остаётся отдельным случаем. Не используйте рабочую установку без восстановления.

До запуска фиксируются версия/канал/хэши, права и путь установки, копия профиля и контрольные суммы истории Lab. В тестовой копии нужны совместимые пользовательские правки баланса, включая значение, равное прежнему default, 0 и false. Исходные рабочие данные не меняются. Автоматический запуск выполняется с `-noaudio -muted` с самого старта через проверенный маршрут передачи аргументов.

Успех требует доказательств **всех** пунктов:

- Переход начинается из старого клиента штатным автоматическим обновлением; новый установщик вручную не запускается.
- Зафиксированы версии/хэши применённого пакета, цепочка процессов и передача исходных аргументов; завершение процессов не уничтожает единственную копию данных восстановления.
- Новая версия возвращается в рабочее меню; её собственный проверяемый сигнал готовности относится к текущей попытке. Одного появления процесса недостаточно.
- Совместимые значения пользовательского баланса, история и неизменяемые хэши/даты/источники сохранены. Отдельно проверены default/0/false.
- На согласованных точках сбоя (до замены, во время применения, до готовности меню) установка восстанавливается до запускаемой версии; данные профиля не теряются. Точные команды инъекции сбоя готовит агент после подтверждения механизма восстановления.
- Результаты, журналы без секретов, идентификатор пакета и исходный/итоговый отчёты сохранены. Неисполненные пункты — NotRun; отсутствие ошибки не означает Pass.

Инвентаризация — подготовка к этой проверке. Она не закрывает автоматическое обновление, Windows/UAC/ACL, восстановление, нативную приёмку или разрешение выпуска.
