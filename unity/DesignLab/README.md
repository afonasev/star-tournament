# Авторские данные Lab

`authoring-history-v1.json` — источник профилей, сохранённых версий и релизных отметок dev-клиента. Файл хранится в Git вне `Assets`, чтобы неотмеченные эксперименты не попадали в Player через Resources. Production использует отдельный каталог поставки и собственные данные игрока.

В Editor откройте `Assets/StarTournament/Scenes/ProvingGround.unity` и включите Play: по умолчанию используется этот проект. Тихий запуск Editor: `UNITY_RUN_MODE=shared unity/tools.sh editor -noaudio -muted`. Development Player из отдельно собранной текущей ревизии принимает `-noaudio -muted -labProject /absolute/path/to/star-tournament/unity`; production этот авторский параметр игнорирует.

Сохранение Lab записывает файл, но не выполняет commit/push, сборку или публикацию. После авторской работы просмотрите diff и сохраните изменения обычным процессом Git. Исходные ID, hash и Integrity не редактируются вручную. Компактная схема содержит исходные снимки и совместимые представления: `Number` может быть внутренним ключом; подписи и проекция опубликованных версий сохраняют первоначальные номера, даты и снимки.

Первичный импорт выполнен явным `LabReleaseBuild.BootstrapAuthoring` из проверенного каталога этой ревизии. Повторный bootstrap отказывается перезаписывать существующий файл. Проверка без записи: `UNITY_RUN_MODE=shared unity/tools.sh editor -batchmode -noaudio -muted -nographics -executeMethod StarTournament.ProvingGround.Editor.LabReleaseBuild.ValidateAuthoring -quit -logFile /absolute/owned/path/authoring-audit.log`.

Проверки и происхождение исходных данных: `docs/evidence/standard-design-lab/runtime/`. Оставшиеся требования Lab продолжаются отдельно; изменение отметок само не обновляет Resources или установленную игру.

Подготовка следующего каталога: `UNITY_RUN_MODE=shared unity/tools.sh lab-stage-releases`. Команда читает только авторский файл этого проекта и заменяет `Assets/StarTournament/Resources/LabReleaseCatalog.json` всеми отмеченными версиями. Снятая отметка исключает версию из следующей поставки, сохраняя её в авторской истории. Просмотрите diff и сохраните его в Git. Повтор без смысловых изменений не переписывает каталог. Одновременная запись другим автором не поддерживается; обнаруженные изменения исходников прерывают подготовку. Сцена не пересоздаётся и не сохраняется, Player не собирается, публикация не выполняется. Старый необязательный аргумент допускает только точный абсолютный путь авторского файла этого проекта.

Новые технические представления старых собственных профилей сохраняют ссылку на исходный номер/hash. При загрузке они пересчитываются с актуальным Default, сохраняя свой внутренний ключ; чтение файла ничего не записывает на диск. Явное сохранение/копирование создаёт самостоятельный полный снимок; явная отметка полного представления фиксирует его значения. При переключении профиля выбирается последняя сохранённая версия или её представление, а не максимальный внутренний ключ кэша. Старые записи без подтверждённого происхождения остаются самостоятельными снимками.

Если такие ссылки есть, физический формат — Schema3: проверяемая оболочка вокруг прежнего Schema2 payload и отдельного списка ссылок на источники. Старый Schema2 и его checksum читаются без изменений; метаданные не помещаются в список параметров или скрытых overrides. Клиенты без поддержки Schema3 отказываются от чтения, сохраняя исходный файл. Остальные файлы продолжают использовать Schema2. Проверки повторных обновлений: `docs/evidence/standard-design-lab/repeated-upgrade/`.

## Balance-only transition (2026-11-03)

The active editor history is `authoring-history-v1.json.balance-v1.json`. The existing `authoring-history-v1.json` is an immutable legacy source. First opening validates its original checksums, trusted historical metadata and every full revision hash, then creates a separate compact projection and origin manifest; it never replaces the original. Subsequent openings and author edits use the compact file. Default authority, saved versions and release flags remain author-owned. The source full hash and projected content hash are distinct.

`Archive/LabReleaseCatalog-full-v1.json` is the exact prior Resources blob (SHA256 `8a87fcee3a78ea099bc9de0cc29d8bed5abbc9c46cbeb164444b333254ea885e`). It preserves all five original full shipped snapshots outside Unity Assets and supplies authenticated metadata only during first author import. Do not edit or package it. Production ordinary startup uses the 24.5-KB balance catalogue plus a2.4-KB independent final runtime snapshot, trusted code definitions and compact local history. User migration preserves a byte-exact SHA256 archive next to the original and writes a sidecar; normal reopening does not require the archive graph.

The resource Schema4 has one current balance snapshot plus deterministic deltas for all included versions. `BalanceLabConversion.Generate` reproduces this conversion from the immutable original; future author releases use the existing explicit staging command, which writes the compact codec and rejects changes to already published source identities. Staging is source preparation and does not authorize a build/publication. If existing author release flags collide with an already published identity, preserve them and resolve that source conflict explicitly rather than silently renumbering or changing the original.

Only the reviewed IDs in `BalanceLabInventory.cs` belong to Lab. Maps, model/collider geometry, graphics, audio, camera/preferences and engine/query budgets remain independent runtime resources. New saved revisions contain balance values, identifiers and hashes, without retired controls or per-revision descriptor graphs.

The codec projects the already executed production interpretation of each archived release. This preserves the target friendly/self damage multipliers0.75/1 for the current packaged Default. Original saved user/author values remain immutable, including historical0.5/0.5. `RuntimeDesignSnapshot.json` separately preserves22 retired final deviations so removing art from Lab does not reset its approved look.
