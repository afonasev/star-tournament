## Границы работы

- Сохраняй согласованный scope, продуктовые контракты, чужие файлы и процессы. Вопрос/ревью — read-only в текущем checkout, без worktree/claim/planning-записей. Перед разрешёнными изменениями используй собственную ветку/worktree, когда нужна изоляция. Не возобновляй другой change автоматически.
- QA и неизменность тестового контракта — по [qa-scope.md](qa-scope.md); модели и авторизация делегирования — по [model-routing.md](model-routing.md).

- Если решение можно показать визуально, сразу показывай реальные изображения/макеты в чате. Для нечёткого запроса покажи несколько заметно разных направлений в первом содержательном ответе; выбор — до реализации. Сравнение первого реального кандидата — по [context-efficiency.md](context-efficiency.md). Концепт не разрешает runtime-изменения или публикацию.
- Автономные игровые запуски без звука с самого старта: `-muted`, Unity `-noaudio -muted`, браузер `?muted=1` до autoplay. Wrapper передаёт параметр, runtime применяет его до аудиоинициализации на всю сессию без изменения сохранённых настроек. Не меняй системную громкость или чужой звук. Проверяй startup/audio-контракт без слышимого вывода; отсутствие поддержки — открытый gate, невозможная проверка — NotRun. Документируй точную команду/URL. Звук допустим только в запрошенном человеческом тесте.
- Player/build/release/deploy — по [local-development.md](local-development.md); docs/tooling проверяй без Unity по [qa-scope.md](qa-scope.md).

## Сохранение и завершение

Подробный контракт сохранения работы, ownership, cleanup, retention и архивирования — [flow/delivery.md](flow/delivery.md); приёмка и lifecycle — [flow/lifecycle.md](flow/lifecycle.md). Git-отчёт: ветка + SHA и отдельно проверенный факт интеграции. Human/device/visual/audio acceptance не выводится из QA/commit/merge. После сохранения и очистки без оставшихся действий: «Сессию можно архивировать без потери данных»; иначе укажи следующий шаг, исполнителя, blocker и точку продолжения. Архив чата не закрывает продуктовые gates.
