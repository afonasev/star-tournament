# Подробные правила проекта

**Актуальная политика 2026-10-08:** [локальная разработка](../local-development.md). Проверки выбираются по поведению; Player build, standalone smoke и поставка не являются автоматическими gates каждой фичи. Упоминания обязательной сборки/Player ниже действуют только для явно заказанной сборки/приёмки или обоснованной минимальной QA-сборки. Tooling, не меняющий Unity runtime, не требует реального Unity запуска ради одного маршрута команд.


Читай только при триггере из AGENTS.md. Пути в тексте относительно корня проекта.

## Запуски Unity на общей машине

- Все Unity Editor/Player запускай через `~/.local/bin/unity-run` или проектную обёртку `tools/unity.sh` (Star Tournament: `unity/tools.sh`). Общий файл `~/.local/state/unity-run/host.lock` находится вне репозиториев; установка и описание — `~/.local/share/unity-run/README.md`.
- По умолчанию выбирай `--shared`: до четырёх параллельных автономных Editor/Player-команд разных проектов/worktree. Компиляция, EditMode, PlayMode, UI fixtures, программно поданные input events, автономные screenshots и разрешённые сборки используют shared, если не зависят от общего экрана, системного фокуса, физических устройств или измеряемой производительности. Наличие UI, графики, Player или слова input в названии теста само по себе не требует exclusive.
- `--exclusive` нужен для замеров FPS/latency/CPU/GPU и benchmark A/B, автоматизации общего рабочего стола/экранных захватов, переключения фокуса, системного ввода мышью/клавиатурой/геймпадом и проверки через общее аудиоустройство. Перед выбором запиши конкретный общий ресурс или метрику, которым помешает параллельный запуск. Для ручной интерактивной приёмки exclusive держится только на время её сценария; обычное открытие Editor не резервирует весь компьютер без такой причины (`tools/unity.sh shared` либо `UNITY_RUN_MODE=shared` для поддерживающей его обёртки).
- Один canonical Unity project path используется одним Editor; каждый worktree имеет собственные Library, logs, builds, testResults и QA data. Не разделяй Library через symlink. Изолируй также порты, save/config paths и выходные screenshot/build файлы автономных Player; при неизолируемом общем ресурсе используй exclusive.
- Ожидающий exclusive перекрывает admission новым shared даже при свободных слотах. Не ставь exclusive в очередь «на всякий случай» и не держи его между командами. При ошибке выбора отменяй только собственную ещё не запущенную команду и повторяй её с shared после проверки зависимостей; чужие команды и lockfile не трогай. Занятый project path требует ожидания независимо от режима.
- Перед запуском из старого worktree сверяй эту политику с актуальным `.agents/references/project-policy/unity.md` основного checkout проекта; прежние blanket-запреты параллельных запусков и требования exclusive для любого UI/Player не применяются. Наличие чужого Unity другого проекта само по себе не блокирует shared; обходить runner нельзя. Эта политика не разрешает дополнительные Player/release-сборки или поставку.
- Старые `unity-runtime` JSON leases, ручные ACK/HOLDNEXT и резервирование за сессией заменены этим механизмом. Не создавать вопросы/зависимости OpenSpec ради ожидания runtime и не опрашивать соседние сессии. Обёртка сама ждёт ресурс только на время команды; planning/integration leases перед ожиданием освобождаются.
- Запускай direct executable, не `open -n`/Unity Hub. Не удаляй/не заменяй lockfile и не останавливай чужие процессы. При прерывании client живой Unity остаётся защищённым до выхода; ожидающая команда отменяется. Старые worktree должны получить актуальную обёртку перед следующим запуском.
