# Контекст текущего среза

Читай для длинной задачи, batch-работы, после первого compaction или перед handoff.

- Один согласованный change/связный проверяемый срез — одна исполнительная сессия. Follow-up относится к той же незавершённой фиче; независимая фича требует отдельного scope и авторизации.
- После первого compaction сохрани scope, проверенные факты и оставшиеся gates. После второго заверши текущий атомарный срез и уже начатые обязательные проверки, сохрани commit/checkpoint и handoff; следующий срез выполняет преемник. Не прерывай проверку ради счётчика.
- Для незавершённой уже разрешённой задачи при насыщении самостоятельно создай один заменяющий чат с тем же scope, полномочиями и модельным правилом; повторного вопроса человеку не нужно (решение 2026-10-22). Преемник сначала читает и подтверждает сохранённую точку, затем принимает ownership/claims и ресурсы. Старый владелец прекращает новые поручения и работу после передачи. Не держи planning/integration lease через handoff и не дублируй исполнителей. Передача не закрывает цель и не даёт новых разрешений на full/install/release/deploy или независимую работу.
- Handoff: цель/change ID, branch/SHA, spec revision, проверенные PASS/FAIL/NotRun, следующий шаг, blocker, ownership/ресурсы и ссылки на evidence. Историю и завершённые чеклисты не копируй.
- Для визуального handoff сохрани выбранный концепт, последний реальный кадр и последнюю удачную версию с путями/ревизиями; покажи их рядом на сопоставимых ракурсах. Укажи до 3–5 фактических видимых расхождений, не выдумывая недостающие. После двух неудачных итераций пересмотри способ моделирования или исходную основу перед следующей попыткой. Галерею истории оставь по ссылке; технический PASS не заменяет визуальную приёмку.
- Читай skill текущей фазы и reference при первом применении по триггеру. Повторно — только изменившийся или недостающий после compaction диапазон; сохраняй путь/ревизию и применимые пункты. Перед мутацией проверяй актуальное изменчивое состояние.
- До чтения большого исходника найди символы через rg, затем читай диапазоны. Независимые read-only вызовы объединяй; фильтруй вывод до передачи модели. Полные логи/evidence сохраняй в файлах, в переписку возвращай сводку, ошибки и нужные доказательства. Изображения для выбора и QA показывай реально.
- Повторяй QA после относящейся правки/ошибки; commit и metadata сами по себе её не инвалидируют. Release/visual/audio/device/human gates и тестовые контракты сохраняются.
- Для ожидания процессов и чатов используй шаблоны [coordination.md](coordination.md).
- Модель и разрешённое делегирование — по model-routing.md. Не создавай подагента ради короткой сводки; пакеты дели только при существующей авторизации и проверяй возвращённые evidence. Для historical browser QA держи один dev-server/origin и объединяй DOM/screenshot/console, где возможно.

Для многоэтапного игрового среза применяй [цельный игровой результат](initiative-execution.md): компактное активное состояние без вложенной истории, синхронные status/source/next, сохранение полномочий и рабочего окружения при handoff. Существующие явные session fences и специальные содержательные проверки проекта сохраняются.
