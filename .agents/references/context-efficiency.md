# Контекст текущего среза

Читай для длинной задачи, batch-работы, после первого compaction или перед handoff.

- Один согласованный change/связный проверяемый срез — одна исполнительная сессия. Follow-up относится к той же незавершённой фиче; независимая фича получает отдельный scope. Новый пользовательский чат требует существующей авторизации, включая применимое поручение координировать инициативу до конца; насыщение контекста само по себе её не даёт.
- После первого compaction сохрани scope, проверенные факты и оставшиеся gates. После второго не начинай следующий срез, batch или соседнее исследование: закончи текущий атомарный срез, уже начатые нужные проверки, commit и handoff. Не прерывай проверку ради счётчика. Общая цель остаётся открытой; автоматическое продолжение «доведи до конца» не разрешает новый срез в насыщенной сессии.
- Handoff: цель/change ID, branch/SHA, spec revision, проверенные факты, следующий шаг, blocker, ownership/ресурсы и evidence. Не копируй историю и завершённые чеклисты; при разрешённой смене координатора передавай ownership до завершения старого.
- Для визуального handoff сохрани выбранный концепт, последний реальный кадр и 3–5 видимых расхождений с целевым видом; укажи пути и ревизии. Если расхождений меньше, перечисли фактические, не выдумывай. Галерею истории держи по ссылке, не загружай её целиком.
- Читай skill текущей фазы и reference по его триггеру. После первого чтения фиксируй путь, ревизию и применимые пункты. Повторно читай изменившийся файл или диапазон, нужный для нового решения; после compaction восстанавливай недостающий контракт точечно. Перед мутацией проверяй актуальное изменчивое состояние.
- До чтения большого исходника найди символы через rg, затем читай диапазоны. Независимые read-only вызовы объединяй; фильтруй вывод до передачи модели. Полные логи/evidence сохраняй в файлах, в переписку возвращай сводку, ошибки и нужные доказательства. Изображения для выбора и QA показывай реально.
- Повторяй QA после относящейся правки/ошибки; commit и metadata сами по себе её не инвалидируют. Release/visual/audio/device/human gates и тестовые контракты сохраняются.
- Для процессов следуй coordination.md: длительную неизменившуюся работу ожидай 30–60 секунд или до события в пределах API, без короткого постоянного polling.
- Модель и разрешённое делегирование — по model-routing.md. Не создавай подагента ради короткой сводки; пакеты дели только при существующей авторизации и проверяй возвращённые evidence. Для historical browser QA держи один dev-server/origin и объединяй DOM/screenshot/console, где возможно.
