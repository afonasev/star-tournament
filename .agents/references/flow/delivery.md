# Delivery, concurrency and cleanup

Read project profile; never execute missing or guessed commands. Shared planning root is not the code worktree. Each implementation works on its owned branch/worktree and records ownership at start (session, branch, worktree, baseline main revision, process IDs and paths). Capture pre-existing status. Record exact spec revision used.

Use the integration lease for merge, canonical spec sync and deployment; use the planning lease for shared artifact edits/commits. Lock order is integration then planning; never reverse it. Release planning before long tests when safe. Do not wait for human responses holding either lease. No lease auto-stealing: confirm prior owner is stopped and inspect Git/deploy state before `lease recover` with a recorded reason.

Before merge refresh main, check unrelated changes, integrate only selected commits, resolve ordinary conflicts within scope and rerun affected checks. Synchronize selected spec deltas while preserving already integrated/newer requirements. Record a per-change spec-sync revision so archive does not reapply obsolete deltas. Check current release immediately before deploy; after deploy verify release identity and smoke at actual URL. Project profile must explicitly authorize this environment. No automatic production permission from this template.

Copy evidence/acceptance assets to a durable configured location and verify links before deleting worktree. Commit owned changes. Verify integrated commits are in main, worktree clean, resources belong to the task, and no active session uses them. Remove owned worktree and local branch with normal safe Git operations, no force deletion. Remote task branches are removed only when merged, owned, and not used by open reviews/other work. Unknown resources are reported, never swept. Stop owned dev servers only after verifying process identity.

Finalize from a stable checkout outside the worktree being removed. If the desktop task is attached to that worktree, use supported handoff or a separate finalization session; leave `finalizing` if self-removal is unsafe. Remove temporary spec/config branches as well. Acceptance uses fresh worktrees for fixes, not retained implementation branches.

Each session startup/end checks inbox for finalization debt and its own dirty resources. Power loss may leave resources; retain ownership and stage so the next session can reconcile. `cleanup` evidence must include actual checks, branch/worktree removal, durable evidence paths and remaining foreign/active resources. Never assert whole-repository cleanliness while other workers legitimately have uncommitted work.

Archive after human acceptance and resolved questions. Acquire planning lease, inspect latest canonical specs and the recorded sync evidence. If deltas already integrated, use supported archive skip-sync behavior only after verifying equivalence; otherwise sync safely. Run strict validation. Record archive location, commit archive changes and commit closure metadata; verify planning checkout clean. Metadata-only closure commits need not trigger app deployment. The archive record retains child/parent links, acceptance and release history.
