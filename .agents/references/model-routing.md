# Маршрутизация моделей

Прочитай этот файл перед выбором модели, делегированием или запуском custom agent. Основная модель для реализации и работы с OpenSpec — GPT-6 Sol/medium. GPT-6 Luna подходит для ясной ограниченной задачи; Spark — для минимальной механической правки.

## Spark и Luna

- Используй Spark только когда модель доступна. Если она недоступна, выбери Luna для той же узкой задачи.
- Для совсем механической локальной правки с однозначным результатом используй spark_focused или spark_ui. Для понятной ограниченной задачи, требующей большего анализа, используй luna_focused или luna_ui.
- Запускай `spark_focused` для одного изолированного механического среза с известным результатом: локального бага с подтверждённой причиной, одной правки модуля/компонента, focused test, rename/typing, конфигурации или документации. Передай точный ожидаемый результат, границу файлов и одну прицельную проверку.
- Не делегируй в `spark_focused` неопределённую диагностику, выбор продукта/архитектуры, правила или симуляцию, data flow, routing, API/persistence, renderer/asset pipeline, OpenSpec, широкие рефакторинги, test strategy, commit/merge/deploy или несколько срезов. При неопределённости или расширении scope верни работу основному агенту.
- Запускай `spark_ui` для одного локального visual, layout, copy, component-state или touch-фикса существующего экрана, только когда ожидаемое поведение однозначно и достаточно одного узкого патча.
- Не делегируй в `spark_ui` изменения правил, игрового состояния или симуляции, data flow, routing, API, persistence, PWA/bootstrap/runtime, архитектуры, renderer, asset pipeline, нового design-system primitive, OpenSpec, тестовой стратегии, commit/merge/deploy или работу по нескольким экранам.
- Передай экран/route, единственный ожидаемый результат и обязательную browser-проверку. При расширении scope верни работу основному агенту.

## Astra

- Используй GPT-6 Astra для архитектуры, сложной диагностики и по прямому запросу пользователя; явный выбор модели всегда имеет приоритет.
- Запускай read-only `astra_architect` до решения, если есть архитектурный выбор с несколькими вариантами, нетривиальная оптимизация нескольких подсистем с измеримыми trade-offs, AI-логика/обучение/стратегия либо изменение контрактов трёх и более модулей. Явный выбор пользователя другой модели имеет приоритет.
- Передай задачу, действующие спеки и критерии успеха. Дождись decision memo с фактами, вариантами, рисками, метриками и планом проверки; реализацию ведёт основной агент.
- Не запускай Astra для локального бага с подтверждённой причиной, однозначного рефакторинга, маленькой UI-правки, механической настройки, одного теста или простого измерения без архитектурного решения.
