# Перенос на другое устройство

Читай при первом запуске на новом устройстве, отсутствии инструмента/store или восстановлении checkout. Все ссылки `.agents/...` в инструкциях разрешаются от корня этого репозитория. `AGENTS.md` — автоматически обнаруживаемое ядро; references не загружаются автоматически: читай их только по указанному триггеру. `.agents/skills/*/SKILL.md` — проектные skills; Claude globs и произвольные `agent.md` не являются автоматическим источником Codex.

Переноси этот Git-репозиторий вместе с `.agents` и `.codex`; глобальный AGENTS и личные skills не обязательны для проектных правил. Не копируй credentials, trust/security-настройки и состояние чужих сессий. `.env` и доступы восстанови отдельно через штатные секреты. Недоступный connector/CLI — явный blocker только соответствующей операции; не подменяй его данные догадкой.

Пути из истории/evidence остаются историческими идентификаторами. Не переписывай receipts, hashes, claims и immutable artifacts ради смены устройства. Для активных конфигураций сначала найди текущий основной checkout через `git worktree list --porcelain`; путь worktree не равен каноническому root. Read-only работа не требует worktree или регистрации planning.

## Workflow и planning

Профиль: `planning/workflow/project.json`; store ID: `star-tournament-planning`. Абсолютные значения профиля описывают текущее устройство, а не обязательное расположение. Перед записью или запуском flow на новом устройстве выполни привязку:

1. Восстанови основной code checkout. Если planning отдельный Git, восстанови его **один раз**, общий для всех code worktree, с исходной Git-историей; не создавай пустую замену и не копируй evidence по задачам.
   Расположение этого store: `<code-root>/planning`. У store сейчас нет remote. До переноса сохрани его отдельным Git bundle (`git bundle create <transfer.bundle> --all`, затем `git bundle verify <transfer.bundle>`) или согласованным Git remote. Сначала владельцы сохраняют незакоммиченное состояние; bundle не содержит dirty/untracked/ignored evidence. Их нужные файлы передаются отдельно с manifest/hash. Без исходной истории восстановление planning заблокировано; кодовый clone не является её копией.
2. В профиле укажи фактические абсолютные `code_repo`, `planning_root`, `evidence_root` и, если применимо, `publication_repo`; сохрани store ID, команды, версии и разрешения. Не подставляй буквально `<code-root>`. Старый путь не нужно создавать на новом устройстве.
3. Проверь установленный OpenSpec через `openspec --help`; зарегистрируй восстановленный store: `openspec store register <planning-root> --id star-tournament-planning` и сверь `openspec store list --json`. Если команда недоступна в установленной версии, останови эту операцию и установи совместимый CLI по проектной документации. Не заменяй shared store локальным `openspec/`.
4. Проверь статус Git обоих репозиториев, актуальные leases/ownership и разреши только собственные пути. Из code worktree используй тот же зарегистрированный root. Перед helper прочитай его `--help`; `python3 tools/flow.py --root <planning-root> inbox` — чтение состояния, не разрешение захватить чужую задачу.

## Unity runner

Unity и общий host runner — внешние зависимости машины. До первого запуска проверь версию из `ProjectVersion.txt`, проектную обёртку и `unity-run --help`/`--status`. Установи совместимый runner на целевую машину: shared admission, exclusive для общего экрана/устройств/замеров, сериализация canonical project path, удержание lock до выхода workload и передача exit code обязательны. Не обходи отсутствующий runner прямым запуском Unity. Установка runner не разрешает менять чужой lock, процессы или системную громкость; пока runner не подключён, Unity QA — NotRun. Проверенный исходный пакет включён в `.agents/tools/unity-run/` (Python 3 stdlib/POSIX). На новом POSIX-устройстве проверь пакет, скопируй `unity_run.py` в устойчивый `~/.local/share/unity-run/`, установи executable bit и создай `~/.local/bin/unity-run`, указывающий на эту копию. Не ссылайся из host installation на временный code worktree. Если runner уже установлен, сначала сравни версию/контракт; не перезаписывай чужую установку и не меняй lockfile. На Windows этот POSIX-пакет неприменим: нужен совместимый host runner, до подключения Unity QA остаётся NotRun. Установка — отдельная операция настройки машины; текущая документационная правка её не выполняет.
