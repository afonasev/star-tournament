# Скриншоты в changelog

Иллюстрация принадлежит конкретному пункту review и конкретному релизу. Используйте реальный кадр проверяемой версии; концепты и кадры другой версии не подтверждают изменение. Снимайте только изменения, которые полезно показать игроку. Публикация остаётся отдельной командой человека.

В необязательный `images` пункта `changes` добавьте:

```json
{
  "path": "screenshots/arena.png",
  "sha256": "<SHA256 подготовленного PNG, 64 строчных hex-символа>",
  "ru": "Арена «Колодец»: обновлённые стыки стен.",
  "en": "The Well arena: updated wall joints."
}
```

`path` задаётся относительно review JSON. Кадр и review храните вместе до подготовки релиза. Один пункт может содержать несколько кадров, весь релиз — до 12. Подписи обязательны на обоих языках, обычный однострочный текст до 300 символов. Markdown-ссылки и скобки в подписях не допускаются.

Профиль `history-png-v1`: PNG, не более 1600×1200 и 2 MiB на кадр, 8-bit RGB/RGBA без interlace. Перед вычислением SHA уменьшите кадр до размера, при котором изменение читается в области истории, удалите посторонние метаданные и проверьте изображение визуально. Поддерживаются IHDR/IDAT/IEND и цветовые/размерные chunks sRGB/gAMA/pHYs/cHRM; анимация, сжатые метаданные и повторный IHDR отклоняются. PNG не растягивается с изменением пропорций. Если для мелкой детали требуется больший размер, используйте читаемый фрагмент кадра с понятной подписью.

Offline render: добавьте `--version <номер>` к обычному `release_changelog.py render`. Publisher сам использует номер целевого релиза. Он проверяет bytes/hash/PNG до packaging, копирует неизменные файлы в `OUTPUT/history-media/history-<sha256>.png`, записывает их identity в `release-notes.identity.json` и включает в общий manifest/uploads/readback. RU/EN Markdown содержит одну и ту же release asset URL с разными подписями непосредственно после пункта. При resume отличающийся body/review/media отклоняется; опубликованные assets не заменяются. Старые текстовые reviews не требуют новых полей.

Launcher запрашивает картинки только выбранной версии, проверяет release URL, ограниченные HTTPS redirects, hash, PNG и размеры; сохраняет их атомарно в отдельном кэше до 64 MiB с вытеснением старых кадров. На кадр действует сетевой timeout 10 секунд. Картинки не являются update packages и не меняют candidate/consent. Закрытие истории и смена версии отменяют запрос; match ack ждёт также media drain. Unity читает локальные bytes и проверяет hash вне render thread, декодирует bounded PNG, сохраняет пропорции и освобождает текстуры при закрытии/смене версии. Offline доступны ранее кэшированные кадры; недоступность картинки не скрывает пункт и подпись.
