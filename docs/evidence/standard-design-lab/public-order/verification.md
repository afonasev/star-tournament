Источник бага: AuthorDefault и LatestAvailableRevision сравнивали physical Number; Save использовал только max physical key. Current counterpart старой опубликованной v1 может получить physical8 рядом с current public v7/physical7. Тогда author startup/reset/default lookup и profile chooser выбирают старую v1. Другой пример: public v7 дедуплицирована в physical1; следующая Save ошибочно получает public2 вместо8.

Изменение: saved order использует ReleaseNumber для bound опубликованных rows, обычный Number для standalone own saves; derived caches исключены, current counterpart предпочитается при одинаковом public number. Save резервирует максимум technical keys и public saved numbers. Не угадываются старые untagged caches и не меняются источники/hash/date/флаги/каталог.
