# macOS recovery supervisor — подключённый маршрут
Baseline964aa66b, codex/game-standard-alignment, child align-standard-startup-recovery. Windows и data/migration contract ещё не реализованы; весь UPDATES-RECOVERY-01 не закрыт.

Launcher Apply теперь сохраняет полный подтверждённый .app до handoff и запускает StarTournamentLauncher из snapshot в режиме --recovery-supervisor до VelopackApp initialization. Runtime и updater берутся из working snapshot вне заменяемого .app. Supervisor проверяет snapshot/identity/frozen signed envelope и exact caller pid+start/path, подтверждает handoff, ждёт launcher и живой orphan Player под per-app lock. Затем копирует и проверяет пакет в own stage и вызывает сохранённый UpdateMac apply --silent --rootDir … --packageDir … --package … --norestart. Игру запускает отдельно с прежними аргументами, -muted/-noaudio сохраняются.

Новая версия должна подтвердить startup через подключённый version/token/menu-ready контракт. Ошибка native update, несовпадение readback, отсутствующий launcher или exit до ready приводят к восстановлению после фактического завершения процессов. Таймаут не убивает Player. Неопределённость процесса на macOS (ошибка3 между HasExited/StartTime) перепроверяется и оставляет ожидание, не даёт разрешения на замену. Elevated/root Mac supervisor запрещён; этот normal-user код не используется как Windows privileged broker.

Same target остаётся blocked, legacy apply-error и signed staged manifest восстанавливаются. Явный повтор разрешается только после restored cleanup. Для отложенного запуска существует watch mode. До подтверждения сохраняется `Restore-<id>.command` в `<launcher-state>/<appId>.recovery-<installation-id>/`: он исполняет retained host и работает при отсутствии нового launcher/повреждённом config, даже когда ни один supervisor уже не работает. Нужно закрыть игру, выполнить этот файл, затем запустить игру обычным способом. Это доступное восстановление, не автозапуск приложения после reboot. Ручная команда не откатывает confirmed релиз после принятого startup.

Backup удаляет новый launcher только после освобождения supervisor lock. При отложенной/неуспешной уборке settled healthy версия остаётся играбельной; новые обновления ждут cleanup. Удаление snapshot теперь имеет durable deletion intent, поэтому interruption между частичным удалением и journal acknowledgement не теряет ownership. Private stage имеет собственный owner; чужие staging данные не удаляются. Неудачный ACK останавливает только собственный ещё не активировавший update supervisor, проверяет неизменность current и оставляет старую версию играбельной.

## Доказательства и пределы
Actual .NET source, отдельные процессы, локальные .app fixtures, RSA-PSS подписанный package fixture и настоящий writer/health journal.9 процессных сценариев: success, exit-before-ready, missing launcher, updater partial failure, wrong readback, deferred, orphan Player, manual command без live host и с broken new launcher/config, wrong ACK. Unicode/spaces/apostrophes в путях/args, quiet args, retry/cleanup и отсутствие оставшихся fixture процессов проверены. Native updater и приложение в этих тестах заменены процессными fixtures: это не настоящий Velopack install/Player/device acceptance.

40 filesystem recovery cases,12 paired writer/monitor и29 journal cases passed. Последний supervisor10/10 в mac-root-final.log:9 процессов+отдельный contract установки. Установленный настоящий UpdateMac1.2.158 проверен только --help и apply --help, бинарный SHA/config/links в mac-installed-layout-readonly.json. Игру и updater apply к установленному .app не запускали. Полный suite/Unity/Player/release/build/deploy в этом срезе не запускались; неизменённые native4 Editor cases от964aa66b переиспользованы.

Readonly layout обнаружил обязательный `Contents/MacOS/sq.version -> ../Resources/sq.version`. Core теперь разрешает относительные parent links только внутри bundle, пошагово раскрывая intermediate symlinks до обработки ..; lexical normalization не используется как доказательство безопасности. Escape, absolute, dangling и cycle отклоняются. Все9 процессных supervisor fixtures содержат настоящий такой sq.version link; отдельные tests проверяют restore/escaping chain/cycle. Xattr/framework/mode контракты сохранены.

История проверок сохранена: first — неверное число argv у нового supervisor (исправлено6 аргументов); compatible —7 сценариев до гонки наблюдения завершившегося процесса в cleanup (исправлен повторный probe, killing только при свежем exact pid/start). Контракты и timeout не ослаблялись. Остальные прогоны7/9 и последний9 успешны. Старые source snapshots логов не считать final proof вместо последнего hash record.

Следующее: protected Windows snapshot+bootstrap+UAC recovery и сохранность/совместимость данных. Настоящий установленный macOS/Windows launcher+Player, подпись/metadata/permission behavior и user acceptance остаются отдельными gates. Нет разрешения на публикацию или установщик.

Дополнительно: journal и backup store привязаны SHA256 к абсолютному installation root. Другая копия приложения с тем же appId не наследует healthy; direct check10 это подтверждает. Legacy apply-error и singleton player lock остаются per-app. Старые промежуточные developer startup journals без root key не считаются доказательством здоровья; prefs/Lab/user data не мигрируются и не удаляются.

ACK pipe принадлежит старому launcher и закрывается при handoff. Updater и replacement (включая Unity descendants) получают независимые stdin/stdout/stderr через фиксированный `exec "$@"` с /dev/null; executable/args передаются отдельными argv и не вставляются в shell code. Native updater пишет --log в собственный файл. Fixtures явно пишут stdout/stderr, проверяя этот переход; пути и args содержат апострофы. Public Mac supervisor отвергает root/elevated запуск.

После добавления проверок stdout обнаружена гонка самого fixture: File.Exists был виден до завершения JSON-записи process marker (mac-supervisor-output-final.log). Fixture markers исправлены на flush+atomic rename, assertions/timeout сохранены. Финальный mac-root-final.log10passed, mac-root-journal29, mac-root-health12. Результаты текущего source snapshot — mac-verification.json; Windows и реальные platform gates по-прежнему открыты.
