Это source-established conflict, а не наблюдавшийся запуск Windows. Нужно исправить текущий native apply route перед проектированием bridge вокруг живого supervisor.

VelopackApp.cs fast callbacks завершают процесс после callback; прежний released app не регистрировал callbacks и исполняет пустую default ветку. Temp path = PackagesDir/VelopackTemp/tmp_<16 random>, где released elevated broker передаёт protected maintenance/staging/<id> как --packageDir, а finally удаляет staging. Этот lifetime нельзя подменить неизвестным packages/default-temp путём.

## Следующий обязательный этап
Сначала устранить зависимость текущего protected apply от resident supervisor, который native apply выбирает для termination. Выбрать фактически проверяемый маршрут: целиком наш recoverable full-payload transaction либо защищённый внешний orchestration host/точно ограниченный updater protocol. Не ослаблять process fence/ACL и не выдавать polling/standalone hook за recovery. Затем signed candidate/broker1→2, startup/retry/argv/normal-user coordination, bounded legacy capture и constrained first-bootstrap producer. У hook15s и first-transition startup failure есть реальные границы: не обещать старому бинарнику новых гарантий. Emergency installer допустим только как recovery, не ordinary update.

find-docs рассмотрен для callback API; ctx7 отсутствует, поэтому использованы закреплённые первичные исходники, не память о API. Сторонние исходники/полные скачанные пакеты воспроизводимы с upstream/tag URLs; в Git сохраняются hashes/идентичности/выводы и скрипты. После сохранения доказательств собственные временные downloads/source copies удаляются. No Player/installer build, full suite, game run, native Windows execution, release mutation/deploy. UPDATES-INSTALL-02 и текущая native Windows acceptance остаются OPEN.
