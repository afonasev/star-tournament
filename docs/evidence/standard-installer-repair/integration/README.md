# Windows07 — NSIS/privileged routing source integration

Baseline `c3a521db`, branch `codex/game-standard-alignment`. This implements the approved system wizard content07 in source and connects the transaction core. It is not an installer build, Windows rendering or device acceptance result.

## Implemented routing

The directory page verifies free space through MUI's `VERIFYONLEAVE`/GetInstDirError route before staging. It resumes interrupted owned work, verifies protected Program Files/marker/top-level contents and identifies fresh, same-version repair or newer upgrade. The custom page skips fresh installs and shows selected path, installed/candidate versions, preservation of settings/profiles/history, and Восстановить/Обновить on the normal wizard button. Native label layout is bounded to132 dialog units; actual Windows rendering remains pending. A dialog-creation error quits rather than skipping confirmation. Begin returns the exact inspected mode/version; if it changed since review, the wizard aborts the untouched stage and asks to review again.

All embedded broker/runtime files are extracted into a unique protected temporary directory directly inside Program Files, using NSIS GetTempFileName. An owned product/PID marker is closed before large runtime extraction. Privileged commands validate source directory/file owner/ACLs, protocol2/candidate identity and that their source lies outside the replaceable root. Dead marked `*.tmp` source directories are cleaned only after trusted-tree checks and proof that neither the parent PID nor an orphan broker is active. Unknown/malformed/uncertain resources are retained. GUI-end cleanup removes the exact source directory or its placeholder. Actual custody/cleanup ACL behavior on Windows remains NotRun.

The broker serializes product registration and root mutation with product+per-install leases. A protected root-bound PID/start-time owner record spans the whole NSIS transaction, including extraction, and prevents a second live wizard from recovering/replacing its stage. Caller elevation/session/SID and source custody PID are checked. Owner writes are atomic; settled cleanup removes known metadata sidecars. Uninstall refuses an unfinished owned transaction; updating and manual update-recovery also refuse installer state. These checks do not claim verification of every legacy binary concurrency case.

NSIS extracts every candidate file and generates the ownership marker, installing.flag and uninstaller in fixed sibling stage. INSTDIR remains the final root. It leaves the stage as current directory before broker rename or rollback. Commit rechecks current version and all stage ACLs/files/flag, then swaps whole roots under lease. Fixed HKLM product values are snapshotted before mutation, with a durable applying intent before any registry write. Replay deletes/restores only this product's fixed values and preserves unknown values/subkeys; a failed replay retains its snapshot. Fresh rollback removes an empty newly created registration. Candidate/version/channel/root mismatches fail before replacement.

Finalize validates registration and candidate before committing. A committed backup-cleanup failure is logged/resumable and does not downgrade complete files. Runtime launch is allowed for extracting/committed/restored states and denied during prepared/saved/installed/restoring; uncertainty is an error. This keeps an uncommitted candidate blocked even if another operation disturbed installing.flag. Staged installer state blocks update activation. Start Menu shortcuts are written only after finalization; failure is visible and can be retried by repair. Existing desktop/finish choices retain their defaults, and the existing ordinary desktop Explorer launch path remains.

## Deliberate unfinished edge

Settled machine-wide failed-target history is copied into the new maintenance store while retaining the **final root** identity. An existing retained startup attempt/backup currently **refuses installer replacement**, both in Begin and the portable commit core, instead of discarding the known-good release. Transfer of such snapshots/bootstrap/latches across repair/upgrade is mandatory next implementation work; the installer feature and full recovery are not complete until that edge is supported. Fully destroyed/conflicting installed version metadata also remains fail-closed. Data migration/rollback compatibility and channel UI preferences remain broader parent work.

`verification.json`:40 actual C# transaction cases (six abrupt child exit/reopen cases),13 actual registration snapshot/replay cases,35 protected recovery cases,10 unchanged observer cases,19 Python installer routing/macro cases =117 selected checks. The Windows Registry callbacks and native CLI guards are compiled, not executed on macOS; fake dictionary callbacks exercise the actual production replay loop. Earlier `nsis-first.log` failed two obsolete fresh-only/text-path expectations; tests now retain and strengthen custody/staging/order assertions. Compiler actions in Python are mocked or NSIS `-PPO`; their `Built ...Setup.exe` lines are fixture files, not a shipped installer. No Unity, full suite, Player/installer/release build or publication.

Actual Windows GUI layout, UAC/ACL/Registry, current-directory rename, fresh/repair/upgrade/cancel/crash, shortcuts/finish launch, temp-source recovery and legacy concurrency remain NotRun. Compilation/portable fixtures cannot close those gates. Before any integration/acceptance, finish retained-startup transfer/data compatibility and inspect the full template matrix.
