# Проверка при следующей явно разрешённой публикации
На чистом точном release source checkout подготовить scaffold предыдущего опубликованного тега своего канала; для первого релиза — всю историю. Агент классифицирует все commits, пишет равнозначные player-facing RU/EN пункты, обоснованные technical omissions, очищает pending после coverage. Сохранить review вне checkout или в ignored .local.
Сначала offline render/preview: проверить факты/языки/категории, отсутствие внутренних IDs и заявлений непроверенной готовности. Повторить штатный publisher только в scope отдельной команды на публикацию; --changelog-review обязателен. Проверить GitHub body, release-notes.md/identity/review, одинаковые пары в истории игры, source/channel/tag/custody и readback. Published release не редактировать.
Эти36 Python tests не являются фактической публикацией, Player/physical или человеческой редакторской приёмкой будущего релиза. До отдельной команды никаких build/release/deploy/full gates.
