# Проверка правил и lifecycle

Результат: исходники helper и правила проекта. Unity/runtime/Player/release/deploy не входят в scope. Точная ревизия записана в delivery.json change improve-agent-workflow-efficiency; verification.json содержит хэши исполнявшихся исходников.

1. Проверьте, что переход merged → finalizing требует delivery_scope с result source, непустой причиной и deferred_gates build/player/release/deploy.
2. Убедитесь по affected тестам, что source-only результат не разблокирует зависимости от поставки; удаление marker не меняет этого факта. Cleanup, owner, вопросы, приёмка и archive gates сохранены. Настоящий deployed требует release и smoke.
3. Проверьте правила: после второго compaction завершается текущий срез; длинные процессы ожидаются 30–60 секунд/до события; повторное чтение — по изменению/недостающему контракту; полный набор и поставка отдельно разрешаются.
4. Согласованные ответы: визуальный handoff содержит концепт, текущий реальный кадр и 3–5 фактических расхождений; однозначный change выбирается с объявлением ID/scope без повторного вопроса.
5. Исторические разрешения profile сохранены как история, активного разрешения новой публикации нет.

Старые задачи сада/освещения не мигрированы и их приёмка не переписана.

Для следующей недельной оценки сравните uncached/output на завершённый срез, число compaction, пустых опросов, усечённых outputs и задач, застрявших исключительно из-за deploy. Сравнивайте задачи сопоставимого scope; cached input не равен стоимости.
